# ADR-0035：补哪些知识卡，让数据自己排，别替人判

- 日期：2026-08-30
- 状态：已采纳

## 背景

[ADR-0033](./0033-retrieval-fusion-and-answer-level-evals.md) 修完检索后，剩下的问题变成"内容
不够"：知识库当时没有 buy box/跟卖 卡、没有 review/差评 卡。原计划是"补卡优先级用真实会话
日志定"。

真去看日志：`~/.ivyea/chat_history` 里**只有 21 条非命令提问**，而且基本是开发调试
（"你好"、"检查一下 ivyeaops 的市场调研板块"、"今天是几号"）。**这份数据不存在。**

顺带试了两种"自动判定这是不是知识缺口"的判据，都不可靠：

- **有没有权威卡**：问一个库里根本没有的机制（"亚马逊超级铂金标怎么申请"），照样会有
  官方卡被向量近似捞上来。
- **权威卡的词法分够不够**：同一个编造的问法，在有用户卡的环境里权威卡是 0 张、在只有内置卡
  的环境里却拿到 136 分——差别来自候选池被用户长文章挤占，不是来自覆盖度。

## 决定

**不自动判定缺口。** 改为记录每次亚马逊域检索的**证据强度**（权威卡数量、最高词法分、
命中的卡 id），`ivyea knowledge gaps` 按"证据最弱"排序输出候选清单，补不补由人看。

同时新增两张卡（buy box/跟卖、评论/差评），并确立**诊断树卡**的格式：官方事实 → 诊断路径
（分清是哪一类问题 → 逐步取证 → 动作）→ 护栏。

## 理由

**为什么不硬凑一个优先级**：拿 21 条开发调试消息编一个"运营最常问什么"出来，比没有优先级
更糟——它看起来有依据，实际是编的，而且后面所有补卡工作都会建在这个假前提上。

**为什么记录而不判定**：两种自动判据都实测不可靠（见背景）。把不可靠的判定包装成"缺口清单"
会让人照着它补错卡。如实记录证据强度、排个序给人看，信息量一点没少，但不冒充结论。

**为什么这件事本身值得做**：优先级要有数据依据，而数据现在不存在——那就先把采集补上。
这份日志用一段时间之后，"补哪些卡"才第一次有真实依据。

## 后果

- `ivyea knowledge gaps` 现在能用，但**一开始必然是空的**——这是设计如此，不是坏了。
  render 里明说了"这份清单要靠真实提问攒，用一段时间再回来看"。
- 日志只记查询本身与命中情况，走 `security.redact_text` 脱敏，封顶 2000 条滚动，写失败一律
  吞掉（记日志不能影响检索）。
- 顺带修了一个**同源问题**：`_ensure_evidence_standard` 在证据里一张权威卡都没有、或者问的是
  具名机制（某某认证/等级/权重/指数）时，会把"证据标准"那张护栏卡挂进去。最危险的情形不是
  "没有证据"（那时模型会说不知道），而是**只有一堆用户上传的长文章**——手里有材料又没有官方
  依据，最容易顺着问题把不存在的机制编圆。
- 三个 known_gap 全部关闭（52/52，known_gaps=0）。相应地把那条"必须存在 known_gap"的测试改成
  测**机制**（合成一个必然失败的 known_gap 案例，验证它不拉红门禁但留在结果里），缺口补完之后
  机制断言依然成立。
- 教训：**没有数据时，先建采集，别编数据。** 用 21 条调试消息推出来的优先级，会让后面每一步
  都错在同一个假前提上。
