# ADR-0005 · 长任务不能因为客户端断开就白跑

- **日期**：2026-07-16（v1.8.7）
- **状态**：已采纳
- **依据**：提交 `fix(serve): /v1/chat/stream 加 15s 心跳 + 客户端断开不再打断轮次`

## 背景

工作台调 agent 跑长任务（ASIN 深度审计、市场调研）时长期有两个症状：

1. 前端报超时错误，**但历史记录里其实有完整回答**
2. 用户以为失败了就重试，结果同一件事跑两遍，花两份钱

根因是流式接口的两个假设都不成立：一是「客户端一直连着」，二是「HTTP 超时前能跑完」。
长任务两条都不满足 —— 中间空闲太久会被中间层掐断，掐断后服务端还以为客户端走了就中止轮次。

## 决策

三条一起改：

1. **15 秒心跳** —— 让中间层和客户端知道连接还活着
2. **客户端断开不打断轮次** —— 后端该跑完还是跑完，结果落盘
3. 调用方（IvyeaOps）配套改成**断链后轮询落盘结果，不重发**

## 理由

- 长任务的正确模型是「提交任务 + 查结果」，不是「等一个 HTTP 响应」
- 重发是最坏的处理：后端已经在跑的轮次不会因为前端重发而停止，等于同一件事跑两遍
- 结果落盘之后，连接是否稳定就不再影响正确性，只影响体验

## 后果

- 带知识引证的回答曾因此丢失流式输出（引证门要等全文才能重写），加 `defer_citation_text`
  开关解决
- 引证门重写的**草稿不能外泄给只累加 token 的调用方**（v1.8.8 修）
- 后续所有长任务能力都按同一模式设计
