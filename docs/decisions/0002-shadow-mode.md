# ADR-0002 · 影子模式：动真钱之前先用数据换信任

- **日期**：2026-06-18（v0.4.0）
- **状态**：已采纳
- **依据**：提交 `feat(Tier3 影子模式): 动钱前用数据换信任`

## 背景

这个 agent 的原始职责是巡检并优化 Amazon 广告 —— 改出价、改预算、否关键词。**动的是真钱**，
改错了当天就亏损。

已有的保护是审核制（写操作要人工确认）+ 硬护栏（阈值限制）+ 审计回滚。但这些都解决不了一个
更前置的问题：**用户凭什么相信它的判断是对的？** 第一次让它动手时，没有任何依据。

## 决策

加一档「影子模式」：agent 照常分析、照常给出它**本来会执行的动作**，但不执行，只记录。
跑一段时间后拿实际数据对照 —— 它当初想调的那些出价，如果真调了会是什么结果。

确认判断可靠之后，再放开写权限。

## 理由

- 信任不能靠承诺，只能靠可回溯的记录
- 这个模式的成本几乎为零（本来就要做分析），但换来的是用户敢不敢开写权限的分界
- 对开源用户尤其重要：他们不认识作者，只能靠数据判断

## 后果

- 成为产品定位的一部分：不是「AI 帮你改广告」，而是「AI 先证明自己值得被信任」
- 与之配套的一条硬规则：**数据不够就不动手**
- 广告优化后来演化成「确定性规则引擎 + LLM 复核」而不是让模型自由发挥 —— 阈值和公式写死，
  模型只负责复核和解释。影子模式的记录也因此是可解释的
