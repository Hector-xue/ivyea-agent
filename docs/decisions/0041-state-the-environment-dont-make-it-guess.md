# ADR-0041 · 运行环境是确定事实，直接告诉模型，别让它用工具试出来

- **日期**：2026-09-10
- **状态**：已采纳
- **依据**：2026-09-10 会话；用户实测对话

## 背景

同一批实测里，除了汇报门禁（[ADR-0040](./0040-intent-not-materials.md)），第二大笔开销
是**环境试错**：agent 在一台 Windows 宿主机上按 Linux 习惯上手，连续撞了

- `/tmp` 不存在 → 克隆失败；
- `find` 被 Windows 的 `find.exe` 接管 → 失败；
- PowerShell 复杂命令的引号和 `$_` 被外层 shell 改写 → 连续三次等于没执行；
- `&&`、`;`、`~/`、通配符逐个踩过来。

而当时的 `[运行环境]` 提示里**只有日期**，一个字都没说这是什么系统、`run_command`
背后是哪个 shell。

还有一处更隐蔽的：一段**成功写了文件**的 Python 脚本，因为自己没有 `print`，工具返回的
是 `[退出码 0]（无输出）`。模型据此断定"沙箱不通、复制根本没执行"，放弃了一条本来可行
的路，改去和 PowerShell 的转义死磕。**一句含糊的工具结果，换来了好几轮无效调用。**

## 决策

1. 每轮的 `[运行环境]` 补上操作系统、版本，以及 `run_command` 实际执行的是
   `cmd /c` 还是 `bash -lc`；Windows 上把已知的几条差异直接写明（没有 `/tmp`、
   `~` 不展开、`find`/`sort` 不是 GNU 工具、`&&`/`;`/通配符行为不同），并给出稳妥做法
   ——**一条短命令搞不定就写脚本文件再执行，别靠试错摸边界**。
2. 退出码为 0 但没有标准输出时，工具结果明说"执行成功，只是脚本本身没有 print，
   **不是执行失败**"。

## 理由

**为什么不靠记忆。** agent 有长期记忆，上一轮的复盘里也确实把这些坑记下来了。但下一次
它还是现场又撞了一遍 —— 它自己的原话是"记了但没直接用结论"。记忆是**召回**，要模型主动
想起来并信任；而 `os.name` 是查一次就有的**确定事实**，属于每轮都该无条件摆在面前的东西。
用召回去承载确定事实，就是在赌模型这一轮想不想得起来。

**为什么工具结果的措辞值得单独改。** 模型的下一步完全建立在上一步的返回文本上。一句
"（无输出）"在人看来是中性的，在模型看来足以支撑"这条路不通"的结论 —— 而它据此换的那条
路更贵。工具返回是提示词的一部分，含糊的措辞和错误的提示等价。

## 后果

- 平台事实每轮注入，占几十个 token，换掉的是十来次试错调用 —— 净赚。
- Windows 的那几条是**已知清单**，不是穷举。新踩到的坑该继续往这里加，而不是加进记忆。
- 同类隐患还有别的工具的返回措辞（超时、被截断、空结果），这次只改了"退出码 0 无输出"
  这一条。
