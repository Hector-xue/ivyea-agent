# ADR-0014 · 主脑可以按轮次覆盖，覆盖失败绝不回落

- **日期**：2026-08-21
- **状态**：已采纳
- **依据**：IvyeaOps 任务台「点一下模型名就换主脑」的需求（对应 IvyeaOps ADR-0021）

## 背景

主脑模型一直是**进程级的全局设置**（`~/.ivyea/settings.json` + `/v1/model/configure`）。
CLI 里 `/model` 换模型，换的也是这个全局值 —— 单人单终端，没问题。

但 IvyeaOps 是多用户的，还有一堆定时任务在跑。它想在任务台的输入框上做一枚"点一下就换
模型"的芯片，而唯一能调的接口是改全局：一个人随手试个模型，别人的对话和后台任务会跟着
一起换掉主脑。于是那枚芯片一直只能是个跳转入口。

## 决策

`chat` / `chat/stream` 认一个 `model` 字段（`<provider_id>:<model>`，如
`openrouter:x-ai/grok-4.6`），**只对这一轮生效**，不写任何配置。

不传 `model` 时行为与此前逐字一致。

解析失败一律当场报错，**绝不回落到全局主脑**：
`unknown_model` / `model_key_missing` / `base_url_required`。

同时新增 `POST /v1/model/catalog`：给 `base_url` + `api_key` 就能列出任意 OpenAI 兼容
端点的模型。

## 理由

**为什么不让调用方自己先 configure 再 chat**：那是全局写操作，并发下两个用户各自
configure 会互相踩；而且中途崩了会把全局配置留在别人的模型上。按轮次传参没有这些问题。

**为什么失败不回落**：回落等于给调用方一个假开关 —— 用户在界面上选了 A，跑的是 B，
没有任何提示。真实世界里这种"看起来正常"的错法最难查。宁可当场说清缺哪个环境变量。

**为什么 `custom` 没有 base_url 要报错**：`providers.from_settings` 在 base_url 为空时
会回落到 DeepSeek 的地址 —— 那就变成拿着 A 家的 key 去打 B 家的接口，报错信息还完全
指不到问题上。只有当前主脑恰好就是同一个 custom 端点时，才谈得上"沿用它的地址"。

**为什么模型清单要新开端点**：`/v1/model/providers/{id}/models` 只认内置 provider 表
里那 23 家，密钥也只从本机 `.env` 取。而调用方的槽位常指向内置表里没有的中转商
（apimart、硅基流动），密钥存在调用方那边 —— 两个条件都不满足。

## 后果

- `chat` 的返回与 `chat/stream` 的 `start` 事件里，`model` 字段现在报**这一轮真正用的
  模型**。不传 `model` 时两者本来就是同一个，所以老调用方无感；但读这个字段的人要知道
  它不再等价于 `/health` 里的全局主脑。为此把两处的拼装收进同一个 `_model_snapshot()`，
  避免两边长出差异。
- `/v1/model/catalog` 会让**服务端**去访问调用方现给的地址，所以只放行 `http(s)://`。
  urllib 认 `file://`，不挡就是一个任意读本机文件的口子。
- 调用方要按 `/health` 的 `version` 判断能不能用这个字段：老版本会静默忽略它。
