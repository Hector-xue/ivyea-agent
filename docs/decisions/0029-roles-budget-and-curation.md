# ADR-0029：子 agent 分工、预算按"干活"算、技能库要有人管

- 日期：2026-08-28
- 状态：已采纳

## 背景

前三期把计划、思考、技能三条线做成了运行时能力。剩下四件事，都是"能力有了但没人管"：

1. **子 agent 只有一个写死的角色**。同一段 system prompt、同一套只读工具、同一个步数上限 ——
   查代码和审 Listing 用的是同一句"把交给你的问题查清楚"。路线图 P7 点名要的
   「数据分析 / Listing 审核 / 广告执行 / 知识审核分工」一条没落地。
2. **步数上限量错了东西**。`routing.py` 顶上记着实测：最近 300 次工具调用里 **112 次（37%）
   是纯记账调用**，一句"测试"跑了 18 步、其中 17 步是 `progress_update`/`todo_write`，
   工具自身耗时 0.0s。这些调用不产生任何进展，却和真正干活的调用一样吃配额 ——
   于是"步数上限"量的不是任务有多大，是模型有多爱记账。
3. **没有止损点，只有止步点**。同样 200 步，读几个小文件和反复喂 20 万 token 差着两个数量级。
   一轮可以安安静静烧掉很多钱才撞上限。
4. **技能库没人管**。近百条技能，"哪条是死的""哪两条重复了"只能靠翻目录 —— 等于不管。

## 决策

### 1. 角色做成数据，用户可扩展

`subagents.Role = (system prompt, 工具白名单, 步数)`。内置 6 个；用户可以在
`~/.ivyea/agents/*.md` 里自己加（frontmatter + 正文），同名覆盖内置 —— 对标 Claude Code 的
`.claude/agents/*.md`。

两条硬约束，**靠结构保证而不是靠角色自己记得**：

- **所有角色都是只读的。** `data_analyst` 看着该给 `run_python`，但子 agent 跑在后台线程里，
  写/执行类工具的审批**没有人能应答** —— 主线的做法是弹给用户，后台没有这个"用户"。
  于是它要么被计划模式直接拒绝（现状），要么就是绕过审批执行代码。后者是个洞，不开。
  要算数就把关键数字带回主线算。
- **永远拿不到 `dispatch_subagent`。** `tools_for()` 只在只读集**内部**收窄，越界的工具一律
  丢掉；`dispatch_subagent` 本来就不在只读集里，所以任何角色都够不着。
  （`READONLY_TOOLS = PARALLEL_SAFE | {...}` 这个坑踩过一次。）

角色声明的工具全部越界时**退回只读全集** —— 一个工具都没有的子 agent 只会白跑一轮。

### 2. 预算只数"干活的调用"，另加成本闸

`budget.TurnBudget`：记账类工具（`progress_update`/`todo_write`/`self_critique`/`task_*`）
照常执行、照常进时间线，但**不占配额**。真正会跑飞的是干活的调用，配额也就该只管它们。

配套一道**硬天花板**（预算步数 × 3）：预算退款是为了让真活有配额，不是给死循环发无限票。
`loop_guard` 会先拦，天花板是最后一道保险。倍数来自实测的最坏干活/记账比。

**成本闸 `chat_max_cost_cny` 默认关**（不设就没有）。设了才在越线时停下来汇报 ——
而且收尾文案必须**说清是撞了哪道闸**：步数超了要采取的动作是"说一句继续"，
成本超了是"这一轮已经花掉 N 块钱，你要不要继续花"。这是两件不同的事。

子 agent 有自己的预算，不吃主线额度：派三个去查三件事，不该让主线只剩三分之一配额。

### 3. 技能策展只出建议

`skill_curator` 基于使用统计给三类建议：沉睡、触发词高度重合、`audit()` 不合格。

**默认只打印，`--apply` 才动手，而且动手也只是归档（可恢复）。** 而且：

- **只碰用户自建技能**。内置技能随包发布，归档了下次升级又回来，纯属白折腾。
- **重合与不合格永不自动处理**。合并要判断哪条更好、补齐要写内容 —— 这两件事没有一个
  自动化程序能替用户拍板。
- 「个人技能覆盖内置」不算缺陷，那是本机作者的明确意图。

### 4. 会话后台沉淀技能：默认关

`skill_reflect` 在会话结束时问一句"这一轮有没有值得沉淀的流程"，双闸门照抄
`memory_reflect` 已被验证的那套：显著性门槛（真干了活）+ 证据门槛（同类流程**跨会话
出现 ≥2 次**才建，否则先进待定区）。

**默认关，理由是具体的而不是保守**：技能会被自动注入进后续对话、实打实改变模型行为。
让后台程序自动往里加东西，第一次误判就污染检索。先让用户用一段时间 `/learn` 看清它的水准。

fork 出去的 agent **只拿 `skill_search`/`skill_view`/`skill_write`** 三个工具 ——
它的活是判断和落盘，不是继续干活。

### 5. 续跑：把"停在哪"落盘

撞闸停下来时，`_write_resume_artifact` 给计划打上重规划标记。`/resume` 把计划状态
带进下一轮。此前 `_record_task_interruption` 只在绑了 `task_id` 时生效（serve 的任务台），
命令行这条路进程一退就只剩一句提示文字。

## 代价与边界

- **子 agent 依然不能执行任何东西。** 这是本期最明显的"少做"，理由见上：后台审批无人应答。
  真要给子 agent 执行权，需要先设计一套"预授权 + 事后可审计"的机制，不是这一期的事。
- **成本估算依赖价目表**。算不出来一律记 0 —— 成本闸宁可不拦，也不能因为某个模型没在
  价目表里就把一轮好端端的任务掐了。
- **策展的重合阈值是拍的**（Jaccard 0.5）。可以接受，因为它**只用来提建议**，
  不自动动手；真要自动化才需要把这个数调准。
