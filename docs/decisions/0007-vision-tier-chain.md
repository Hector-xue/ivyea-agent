# ADR-0007 · 视觉三档降级链

- **日期**：2026-08-16（v1.13.0）
- **状态**：已采纳
- **依据**：提交 `视觉三档降级链：主脑没视觉不再等于功能死掉 (#69)`

## 背景

Listing 生成等板块要读图。原来的实现依赖主脑模型自带视觉能力 —— 如果用户配的模型不支持视觉，
整个功能就废了。而开源用户配什么模型是不可控的。

更糟的是一个静默失败：**data URI 图片被丢弃后，模型不会说「我没看到图」，而是开始编造画面**。

## 决策

三档降级，按能力自动分流：

| 档位 | 条件 | 做法 |
|---|---|---|
| T1 | 主脑支持视觉 | 直接读图 |
| T2 | 主脑不支持，但配了独立视觉模型 | 旁路代读，描述回灌给主脑 |
| T3 | 两者都没有 | 本地 CV + OCR 做量化描述 |

**降级了必须明说** —— 界面和输出里都标出当前走的是哪一档。

## 理由

- 自托管产品无法要求用户配特定模型，能力必须能优雅降级
- 静默降级比不降级更危险：用户以为 AI 看了图，实际它在编
- T3 虽然弱，但对「主图是不是白底」「有没有文字」这类判断够用

## 后果

四个踩过的坑，记在这里：

1. **判定要按模型，不按厂商** —— 同一家的不同模型视觉能力不同
2. **T3 的兜底不能顶掉真视觉模型** —— 降级链的顺序必须是硬的
3. **k-means 按亮度播种会塌成白色** —— 本地取色要按色彩空间播种
4. **data URI 被静默丢图**是这条链最初的起因，修的时候要连带堵掉

工作台侧只读 `/health` 暴露的 `vision_chain` 字段来显示当前档位，判定逻辑只有一份，在 agent 里。
