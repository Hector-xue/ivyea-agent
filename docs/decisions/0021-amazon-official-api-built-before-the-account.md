# ADR-0021 · 亚马逊官方 API 先建好，不等某台机器有账号

- **日期**：2026-08-23
- **状态**：已采纳
- **接续**：ADR-8（provider 抽象）、ADR-0020（没数据也照写规则）

## 背景

方案书里 P7（亚马逊官方 API）一直标着"用户决定后延"。后延的真实理由混着两件事：

1. 排期取舍 —— 先把领星用到极限。这是合理的。
2. "我这台机器没有亚马逊卖家账号" —— 这条**不成立**。这套东西要发出去给别人用，
   用它的人有账号、有真实数据。开发机恰好没有账号，是验收时点的问题，
   不是需求范围的问题。这与 ADR-0020 推翻 ADR-0018 决策一是同一个错误。

同时，"没有账号所以不能写"这个论断本身也不牢靠：**SP-API 与 Ads API 的契约是公开且
权威的**（官方 model 文件、官方 Postman 集合），与领星那些没有公开文档的路由
（refundOrders 的响应字段名、广告小时级路由）完全不是一回事。后者不允许凭猜测写，
前者照文档写就是核实过的写法。

## 决策

### 一、先建 P7a（授权 + 客户端 + provider 适配），不等账号

`amazon_auth`（LWA 换 token、区域推导、站点表）、`amazon_spapi`（限流/重试/分页）、
`amazon_ads`（版本化媒体类型、v3 异步报表）、`datasources/amazon_source`
（规范化到既有 canonical 契约）、`ivyea amazon verify`（分步自检）、
以及 IvyeaOps 里可以真正填进去的配置区。

### 二、契约必须逐条来自官方文件，并在代码里写明出处

本轮实际拉取核对的：`amzn/selling-partner-api-models` 的 `fbaInventory.json`、
`ordersV0.json`；`amzn/ads-advanced-tools-docs` 的官方 Postman 集合；
developer-docs.amazon 的 LWA 与 endpoints 两页。写进模块 docstring，
下一个人不用重新考古。

### 三、官方源优先级 50，高于领星的 100；但**不是替代关系**

官方是第一手、延迟更低。但官方不给成本利润（算不出毛利），Listing 快照也要拼三个
接口才凑得齐 —— 那两块仍然只有领星有。**不支持就不声明 supports()**，
指标层会如实报"没有数据源支持该指标"，比返回一堆 0 诚实得多。

### 四、店铺清单退化到亚马逊站点表

不做这一步，只用亚马逊的人**一个店都巡检不了**：目标解析拿不到清单，
每条任务都报"缺少 sid"。清单形状与领星那份逐字段对齐，上层无从分辨来源。

## 理由

**为什么 SP-API 与 Ads 的凭据允许分开又默认共用**：绝大多数卖家两边是同一个 LWA
应用，强迫填两遍只会填错一遍；但广告 API 常常单独审批，"SP-API 通了、广告还在排队"
是很常见的中间态。所以 `supports()` 对两类指标分开判 —— 那时库存规则就该先跑起来。

**为什么广告归因取 7 天**：领星报表就是 7 天口径。取 14d/30d 会让同一个活动的 ACOS
在换源当天凭空变好一截，用户会以为是自己优化见效了。换源不该改变数的含义。

**几个只有照文档写才躲得开的坑**（都在代码注释里标了）：
SP-API 令牌走 `x-amz-access-token` 而不是 `Authorization`（错了拿 403，不告诉你原因）；
2023 年起不再需要 AWS SigV4，网上大量旧教程照抄会白写一堆；
列表参数要拼成 `a,b`，httpx 默认展开成重复 key 而 SP-API 只认最后一个；
`unfulfillableQuantity` 是**对象**不是数字，直接取会恒为 0，让"不可售激增"静默失效；
Ads v3 把花费叫 `cost`（v2 是 `spend`），照抄会拿到一整列 0；
`/sp/campaigns/list` 要版本化媒体类型 `application/vnd.spCampaign.v3+json`。

## 后果

- 已可用：填凭据 → 库存与广告规则改吃官方数据 → `ivyea amazon verify` 端到端验收。
- **仍未做**，且都需要真账号或真基础设施才验得了：
  - P7b 推送通道（SP-API Notifications / Marketing Stream）：要建 EventBridge/SQS
    目的地并真订阅，没有账号连能不能建都不知道。这是"秒级实时"的唯一正路（ADR-9）。
  - P7c 官方写通道（改预算/竞价/改价）：写操作要复用 `lingxing_write` 的七道闸，
    而**闸门逻辑目前与领星耦合**。写错的代价是真金白银，这条要在有真账号能回滚验证
    的前提下做。
  - Buy Box / 订单停滞 / 退款率 / Listing 压制等 P7d 规则：数据面已通（item_offers、
    orders 已封装），规则本身待补。
- 验收状态记为「代码完成 / 待真账号」，不记为完成。这与 L3 Listing 规则同一口径。
