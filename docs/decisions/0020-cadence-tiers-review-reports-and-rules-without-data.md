# ADR-0020 · 节奏改档、周报月报、以及「没数据也照写规则」

- **日期**：2026-08-23
- **状态**：已采纳
- **推翻**：ADR-0018 的「决策一：不做 listing 销量接 L3」

## 背景

三件事凑到一起，根子是同一个：**把「这台机器的账号什么样」当成了「产品该做成什么样」。**

1. ADR-0018 因为本机领星账号里 1200 条 listing 销量全为 0，决定「不做 listing 销量
   接 L3」。但这套东西是要发出去给别人用的 —— 用它的人有真实数据、会配自己的
   API 和 MCP。方案书自己的自检规则第 3 条就写着「当前没有数据 ≠ 这条规则不做」，
   ADR-0018 违反了它。
2. 巡检节奏定的是 L1 每 20 分钟、L2 每小时。20 分钟和 1 小时对「库存断货、活动被
   暂停、预算被外部改动」这类事没有实质差别，却是三倍的接口调用。
3. 只有日报，没有回顾。「这周到底改了什么、有没有变好」没有任何地方回答。

## 决策

### 一、规则照写，验收分两段

listing 维度的 4 条规则（断流 / 销量下滑 / listing 级 ACOS 超标 / 有花费零销售额）
现在就写、用真实响应结构的 fixtures 覆盖阈值边界，接上有数据的账号即生效。
本机账号的验收状态记为「待真数据」，不记为「不做」。

配套的两条纪律：

- **规则只读指标契约**（`volume_7` / `volume_30` / `amount_7` / `spend_7`），
  不关心是领星 MCP 还是 SP-API 给的数。换 provider 时规则一行不用改（ADR-8）。
- **整体性缺失报缺口，不报 N 条告警**。全店 7/30 日销量都是 0，不是"全线断流"，
  是这个源不给销量。逐条报出来是 1200 条假告警。

### 二、节奏改成 1 小时 / 12 小时 / 天 / 周 / 月

默认值集中在 `schedule.PATROL_DEFAULT_MINUTES`，**唯一真源**：CLI、IvyeaOps 界面、
文档都从这里取。界面上每一档可单独开关、可调间隔。

### 三、周报 / 月报是回顾，**不创建审批项**

内容：本期指标 + 环比上一个同长度窗口、本期批了/执行了/否决了/回滚了几条、
还没解决的问题、当前积压。

**不带按钮**是刻意的：同一条建议早报已经给过按钮，周报再给一次，同一个目标就会挂
两条 approval —— 批了其中一条，另一条还在 pending，很容易对同一个活动改两次预算。

## 理由

**为什么改节奏这件事不能只改一个数字**：L2 的花费突增规则靠"当日累计值多次采样做差"
得到增量，基线来自 `intraday` 里存的历史采样。老实现返回的是**两次采样之间的差值**，
在每小时采一次时它恰好等于小时速率，于是拿它和 `per_hour()` 比看着没毛病。
把采样间隔改成 12 小时，基线变成 12 小时总量、当前值仍是每小时速率，一比差 12 倍
—— **规则永远不会触发，而且不报错**。改一个 20 就能把一条止血规则悄悄弄死，
这正是"改默认值不等于改了行为"的反面版本：改默认值把行为改没了。
基线因此改成速率口径，与采样节奏彻底解耦，并加了 ±3 小时的时段容差
（任务按「上次跑完 + 间隔」调度，执行时刻会慢慢漂，要求整点严格相等的话，
漂过一个小时边界基线就凭空消失）。

**为什么 listing 规则一律不带 intent**：快照里没有 listing → campaign 的映射。
凭 ASIN 猜一个活动去改预算，改错的是别人的钱。要动手得先有确定映射，
那是 Ads API 才给得起的东西（P7）。

**为什么周报不是"每周跑一次巡检"**：巡检回答"现在有什么问题"，回顾回答
"这一周发生了什么"。后者的主体是**已经发生的动作**（批了几条、执行了几条、回滚了几条），
那些数据在 approvals 里，跟再跑一遍规则无关。

## 后果

- ADR-0018 的决策一作废。该 ADR 的其余三条决策（一个任务覆盖多店、能力边界不算故障、
  变体合并后再推送）继续有效。
- L2 从"每小时一次"变成"每 12 小时一次"，日内突增的**发现延迟**从最长 1 小时变成
  最长 12 小时。这是明确的取舍：想要小时级发现就把这一档调回 1 小时，
  或者等 P7 接 Amazon Marketing Stream —— 那条通道本来就是推送式的，
  与轮询节奏无关（ADR-9）。
- 采样变稀后，同一天只有一次可用增量（当天首次采样没有增量可比）。
  `l2.baseline_min_days=3` 意味着基线需要 3 天才建立，与改动前一致。
