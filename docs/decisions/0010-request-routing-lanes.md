# ADR-0010 · 按这句话的性质选路线：闲聊 / 板块直达 / 常规

- **日期**：2026-08-18（v1.14.1 之后）
- **状态**：已采纳（已落地）
- **依据**：2026-08-18 会话；对线上 `~/.ivyea/sessions`、`traces.db` 的逐轮取样，以及对
  DeepSeek 官方端点的直接压测

## 背景

用户反馈"回答和执行都特别慢"。先把慢在哪量出来，而不是照直觉优化：

| 环节 | 实测 | 结论 |
|---|---|---|
| 模型单次调用（deepseek-v4-pro，官方端点） | 1.3–2.5s | 不慢 |
| 同上，但挂满 54 个工具 | +0.5s | 不是瓶颈 |
| 本地知识检索 `knowledge.evidence_context` | 0–99ms，注入 0–98 字 | 几乎免费 |
| 技能匹配 `skills.context_for_query` | 7–32ms，但注入 1658 字 | 时间不花，**内容**有害 |
| 工具 schema | 54 个 / 20.7K 字符 ≈ 6.9K token，**每步重发** | 步数的放大器 |

**真正的成本是步数**：每一步都是一次完整往返，而且上下文越滚越大。线上取样：

- 一句「测试」跑了 **18 步，其中 17 步是 `progress_update`/`todo_write`**，工具自身耗时
  0.0s，端到端 2 分 16 秒（首字 132.8s、输入 280.8K token 都是这么堆出来的）。
- 最近 300 次工具调用里 **112 次（37%）是这类纯记账调用**。

直接成因是一个 bug（见 CHANGELOG v1.14.2）：复杂度判据把系统注入的技能手册当成用户
说的话，于是"简单"被判成"复杂"，汇报状态机被强制拉起。但修完那个 bug 之后，更根本的
问题仍在：**所有请求走同一条最重的路**——不管你说的是"你好"还是"把这个仓库重构一遍"，
都挂 54 个工具、都注入知识和技能、都套同一套纪律。

## 决策

在 serve 入口按**用户真正打的那句话**选一条路线（`ivyea_agent/routing.py`）：

| lane | 命中什么 | 改变什么 |
|---|---|---|
| `chat` | 寒暄、道谢、问身份、极简常识（**整句**匹配白名单） | 不挂工具、不注知识、不注技能、关掉汇报状态机 |
| `board` | IvyeaOps 板块任务（市场调研 / 打法 / 关键词竞争 / 审计…） | 工具集**不裁**，但给一条点名到具体工具的直达指令；关掉汇报状态机 |
| `work` | 其余全部 | **与改动前逐字一致** |

配套收紧技能自动注入：只认**名义命中**（id / 标题 / 描述 / 触发词对上），不认正文撞词。

## 理由

**为什么闲聊要裁工具而不只是"少注入"**：注入本身是毫秒级的，省不出时间。裁工具省的是
6.9K token/步，但更重要的是**断了模型"顺手查一下"的念头**——工具摆在那儿，模型就会用，
一用就是一个来回。

**为什么板块任务反而不裁工具**：裁工具省的是 token，缺能力赔的是整件事做不成。板块任务
本来就要调工具，真正该省的是"先分析一轮再想起来该调哪个工具"那几步——所以给的是点名到
`market_generate_report` 这一级的直达指令，而不是把工具集削成一件。

**为什么闲聊走白名单而不是黑名单**：实测反例「新卖家注册身份验证失败怎么办」——一个字都
不在业务词表里，却是标准的知识库问题。走了快车道就等于没查知识库、没挂工具、凭记忆瞎答。
**黑名单永远列不全；判不准要往"多做一点"那边倒，不是往"快"那边倒。** 这条现在钉在
`tests/test_routing.py` 的 WORK 表里。

**为什么这两条 lane 要关掉汇报状态机**：闲聊没有阶段可汇报；板块工具本身就是一次长任务、
自己会回报进度，再套一层 todo 只是挡在实际动作前面。

## 代价与边界

- **白名单覆盖面窄**：只有寒暄/身份/常识类走得上快车道，"看一下广告数据"这种仍是全量。
  这是有意的——快车道的收益（省 2–4s）远小于误判的代价（该查的没查）。
- **板块意图表是硬编码的词表**，IvyeaOps 那边加了新板块工具，这里要跟着加，否则只是回退到
  `work`（不会出错，只是少一次直达）。工具名对着 `ivyea_ops_tools.TOOLS` 写，别凭印象。
- **只接在 serve 上**。CLI 走的是自己的组装路径，判定函数是共用的，但接线要另做。

## 效果

同一台机器、同一个模型，端到端（`/v1/chat/stream`）：

| 输入 | 修复前 | 之后 |
|---|---|---|
| 测试 | 2 分 16 秒 / 18 步 | 7.9s / 0 步 |
| 你好 | — | 5.3s / 0 步（`lane=chat`） |
| 1+1等于几？ | — | 2.2s / 0 步 |
